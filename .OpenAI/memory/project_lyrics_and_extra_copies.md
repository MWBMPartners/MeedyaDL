Built 16 Nov 2026 on `work-in-progress`, reviewed in many rounds by fresh Claude agents (Codex unavailable). The full technical description is in `.claude/CLAUDE.md` (bullets "Companion downloads", "Enhanced LRC", "Metadata enrichment", "Content advisory suffixes", "Internal helpers"). This file is the short map and the reasons.

**Order of steps for one download (#1435).** Snapshot the main download's files, fetch the album details once, Step 0 (iTunes tags), Step 1b (MeedyaDL's own word-by-word lyrics lookup, run BEFORE any rename and before Step 1 tagging), then, on GAMDL 4.0.2+ only and only when needed, a GAMDL word-timed lyrics pass for tracks Step 1b could not check or save, then Step 1 tagging (no renames), cover steps, the lyrics conversions (Steps 2 to 2g), then the album-folder rename, then the per-file renames, and only then the extra-format downloads start. Why: renaming first broke the lookups that match files by name, and an extra copy started early could land on a main file's plain name.

**The companion gate.** Extra-format downloads are spawned early but wait on `lyrics_pass::CompanionGate` until enrichment has done the renames. Dropping the gate (early return, panic, deadline) opens it, so companions are never stranded. If the renames did not finish, companions add a suffix to every file so nothing can land on a main file's name.

**Maintainer decisions.** (1) Extra copies NEVER overwrite: every companion run is forced to overwrite off on every path, so a re-download does not refresh copies already on disk (trade-off accepted). (2) `overwrite` is never written to GAMDL's config.ini, only sent on the command line, because GAMDL 3 cannot cancel an INI `overwrite = true`. (3) On a mixed album (some main tracks already in a format) the copy asks only for the tracks that lack that format, as per-song links; songs that cannot be asked for are counted in one plain log line. (4) Only THIS download's files are renamed, tagged or given lyrics; older files in the same folder are left alone. (5) Nothing in the extra-copy code deletes a file (a test checks it). (6) Ordinary downloads keep GAMDL's `ttml`; `enhanced-ttml` is sent only by the word-level pass.

**Per-file lyrics steps (#1441).** `download_queue/lyrics_steps.rs` holds one function per step for ONE file and `*_for_files` for a list. The old folder-wide conversions are kept only as the reference the parity tests compare with; a test checks `processing.rs` and `companions.rs` never call them. Disc sub-folders are covered. A music video found at snapshot time counts as this download's.

**Lyrics for extra copies and upgrading the main file (#1440, #1442).** After all tiers, `companion_lyrics.rs` gives each NEW extra copy the same lyrics files as the main download (better of the main's and the copy's own: word-timed `.ttml` beats line-level `.ttml` beats `.lrc`/`.srt` only; a tie keeps the copy's own). The reverse also happens: if an extra copy has strictly better lyrics than a main file this run wrote, the main file is upgraded first (`pick_upgrades`, `upgrade_main`), then other copies take the upgraded lyrics. Safety rule: only files this download made are changed; an unknown start time replaces nothing. An extra format's tags (`apply_codec_metadata_tags`) go only to the files that tier added, never the whole folder.

**Unfinished main-file lyrics (catch-up).** `pending_main_lyrics` is set as soon as the snapshot exists. If enrichment stops early (deadline, early return), the files' lyrics are finished by `companion_lyrics::recover_pending` from the extra-copy task, or failing that the completion task. It first waits (up to 5 minutes) for any write job an abandoned enrichment left running (`InFlightWrites`), and a file that panics inside the catch-up is not retried.

**App-wide file write lock rules (#1442).** `utils::file_locks::global()` is the one per-file lock for every tag write. Take it in the per-file loop, never inside the function that writes one file (it is not re-entrant). Use `lock().await` in async code and `lock_blocking` only inside `spawn_blocking` or a plain thread (it panics on an async thread). Hold one file lock at a time and never wait for anything else while holding it. A rename cannot be locked. Any new tag writer must take it; source checks in `download_queue/tests.rs` fail if a write site does not.

**Needs a real machine.** Song-link requests landing with the expected file names; 4.0.2 refreshing an existing `.ttml` when overwrite is off (could replace word-timed TTML in a companion run); long mixed-album runs.

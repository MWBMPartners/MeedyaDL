description: GAMDL 4.0 is a rewrite; MeedyaDL drives it through a separate 4.x path. HIGHEST_DRIVABLE_MAJOR is 4 since 13 Nov 2026, but 4.0.0 is only an opt-in Untested upgrade until real downloads are tested.
type: project

On 2 Nov 2026 the unreleased upstream GAMDL `4.0` branch (commit `0c884ecc`, version `4.0.0a0`) was read file by file. It is a rewrite: no `python -m gamdl` (no `__main__`), downloading is the `rip` subcommand, YAML settings instead of `config.ini`, renamed options, `rich` text output, no helper programs, Widevine moved to an optional `gamdl[widevine]` extra, artwork saved per track, lyrics only `.lrc`/`.txt` (no `.ttml`).

**What MeedyaDL first had (commit `06e5b53` on `work-in-progress`; the switch has since been raised, see below):**
- `gamdl_capabilities::HIGHEST_DRIVABLE_MAJOR` — the on/off switch (3 until 13 Nov 2026, now 4). Above it, `refuse_unsupported_target` refuses the install and the update check marks the release `is_compatible = false`.
- `GamdlCliGeneration` / `cli_generation_of` / `detected_cli_generation`, read from the major number only (so `4.0.0a0` counts).
- `GamdlOptions::to_cli_args_v4` + `gamdl_service::gamdl_v4_args` / `build_gamdl_v4_command`: `python -c "<launcher>" --no-config rip <options> <links>`, stdin closed, `COLUMNS=4096`, `NO_COLOR`, UTF-8 output, `GAMDL_*` env vars removed. Only reached when the installed GAMDL is 4+.
- `process::parse_gamdl_v4_line` for `✓/↷ title: outcome → path`, `✗ …`, `Finished: …`.
- `FFmpegPath` and `NoExceptionsFlag` gates are off from 4.0.
- Hardening from 7 review rounds (later commits up to `14cbaa8b`, issue #1404): 3.x updates stay offered once 4.0 is on PyPI (first `newest_drivable_release`; since 13 Nov `update_major_ceiling`, which also keeps 3.x users from being offered 4.x); `upgrade_pip_engine` refuses `gamdl`; install targets must be plain versions; lyrics-only requests refused on 4.x (it has no such mode — would re-download the album); 30-minute stall floor for silent 4.x runs (`idle_minutes_for`, main + companions); 4.x info lines are `Unknown` (a `ProcessingStep` switches the watchdog off); a 4.x run failing only on "format not available" counts as done with warnings (4.x exits 1, 3.x exited 0); song titles stripped before sorting 4.x errors; PlayReady not passed to 4.x until its install extra is decided.

**Release 4.0.0 (12 Nov 2026):** the preparation was aligned with the released 4.0.0 (49 commits after the branch first read) and checked against a real `gamdl[widevine]==4.0.0` install: plain `--overwrite` switch; `--lyrics-file-format` (TTML back) / `--no-lyrics-file`; always `--no-database` and `--no-tracebacks`; download folder always sent (blank → default Music folder, saved-later folder followed, ".." refused at spawn time); DRM set-up errors kept out of the format fallback. Reviewed in 6 Claude rounds (Codex unavailable), last clean. Switch still off — needs a real download first.

**Switched on (13 Nov 2026, maintainer's request, so alpha has a build to test):** `HIGHEST_DRIVABLE_MAJOR = 4` (GAMDL 5 still refused). Decisions: (1) opt-in only — `tool-versions.toml` still says 3.9.1; 4.0.0 is installed on purpose from Settings > Tools > GAMDL Version Management ("install specific version"); the update check stays within the major version a person is on (`update_major_ceiling`: the tested major, or a higher one already installed), so 3.x users are offered 3.x updates only — an independent review found that offering PyPI's 4.0.0 as "latest" buried every 3.x update; (2) Linux ARMv7 and Windows on ARM stay held by their platform ceilings; (3) PlayReady on 4.x falls back to Widevine with an activity-log line (`plan_drm_backend_on_gamdl_4`), and `play_ready_drm` is false on 4.x. `routine_install_spec` keeps an opted-in 4.x when the setup wizard installs GAMDL again (it used to drop back to 3.x); `install_gamdl` asks the installed GAMDL its version first rather than trusting the remembered one. No settings migration is needed: settings become options per download and 4.x runs with `--no-config`. `get_gamdl_capabilities` gained `gamdl_v4`; `GamdlFourNote` (`src/components/settings/GamdlFourNote.tsx`) marks the settings 4.x does not use (cover art saving/size/raw format, Synced Lyrics Only, Download/Remux Mode, mp4decrypt/MP4Box/N_m3u8DL-RE). Help: `help/tools.md` → "Trying GAMDL 4". Next: real downloads on each platform, then add 4.0 to the tested window.

**GAMDL 4.0.1 (14 Nov 2026; checked 15 Nov from the full source diff and a real install):** same packages and requirements as 4.0.0. 4.0.0 is now refused (`KNOWN_BAD_VERSIONS`): it saved files with a hard link and no fallback, so downloads to exFAT/FAT32 portable drives and many network or cloud folders failed; 4.0.1 copies and renames. The known-bad advice gained a case for a fix that is above the tested limit but installable on purpose (`fix_is_an_untested_release_this_platform_may_install`), and the plain install route moves 4.0.0 to 4.0.1 (not reachable from the app while GAMDL is installed — a 4.0.0 user moves via the Updates page or "install specific version"). 4.0.1 restored `--embedded-cover-size`, `--use-album-date` and `--date-tag-template`; MeedyaDL sends them only from 4.0.1 (`GamdlFourRestoredOptions`). Cover size is always a number, never `max` (4.0.1 raises on `max` for artwork without a size placeholder). Album date and date form are never filled in today (no setting), on 3.x or 4.x. Testers install 4.0.2.

**GAMDL 4.0.2 (16 Nov 2026; checked from the full source diff):** 4.0.1 is now refused too: the generic-key-address filter came in with 9a78275, already in 4.0.0, so both 4.0.0 and 4.0.1 can save some songs still locked while reported downloaded; the fix for both is 4.0.2. The update check skips refused releases. 4.0.2 shares one `Cover` file per album folder again, so `--save-cover` and `--file-cover-size` are sent from there (`GamdlFourSharedAlbumCover`, capability `gamdl_four_saves_album_cover`). Ordinary downloads stay on `ttml` (with `enhanced-ttml` a track with no word timing gets no `.ttml`, and all MeedyaDL lyrics sidecars are built from it). **16 Nov 2026, maintainer's decision:** `enhanced-ttml` is sent only by the word-level lyrics pass (`download_queue/lyrics_pass.rs`, `GamdlFeature::GamdlFourWordTimedLyricsFile` >= 4.0.2): MeedyaDL's own lookup (Step 1b) runs first on every version, now before tagging and before any rename; the GAMDL pass runs only for tracks Step 1b could not check or save, with overwrite off so audio is skipped and only `.ttml` refreshed. Revised the same day after an independent review: the pass runs before ANY rename (folder included) with the primary's own templates, its resolved download folder and only on the GAMDL version the primary run used; the folder and per-file renames come after every lyrics conversion (sidecars incl. `.lyrics` follow); the extra-format copies are held until then (`CompanionGate`; a dropped gate, or a rename that did not land, releases them with every file suffixed and plain-named AAC left out unless the primary's template already had a format suffix) and write into the real album folder via a fixed template, unless an album file template has its own folder level (`Disc {disc}/…`). A companion can never get the primary's file names: the suffix a format fallback appended is recorded on the queue item and exactly that is stripped (a person's own template suffix is never touched; suffixes no longer pile up), and a last per-attempt check compares fully built file templates (only MeedyaDL's own appended suffix counts as the primary's) and every format detected in the primary's files (skip a format the primary already has; on a mixed album ask only for the other tracks as per-track song links in one GAMDL run, overwrite off, never deleting anything; a playlist skips that format with a plain reason; songs left out are counted in one plain line; only THIS download's files (written by this run, or named like its files with a matching album) are renamed and make up the protection and per-track lists; older files are no longer renamed by a later download, including by the final advisory pass, now scoped to this download's files and the copies made after its renames; companions NEVER overwrite — every attempt runs with overwrite off, and copies skipped because the name was taken are counted in one plain line; `overwrite` is no longer written to config.ini at all, since GAMDL 3 cannot cancel it from the command line; a labelled copy already in the folder (`01 Song [Explicit] [Lossless]`) counts as present, so only songs without one are requested), naming the format in plain words when it skips. Step 1b's refused sign-in is judged on the HTTP status, not the message. Needs a real-machine check (no audio re-downloaded, wrapper-only sign-in gets word timing, multi-disc albums). TTML refresh on overwrite-off needs a real-machine check. Audit: `.github/audits/gamdl-v4.0.2-audit.md`.

**Why the switch stayed off until then:** without the refusal, the "Untested" upgrade button would install 4.0 the day it is published and every download would fail on the first line.

**How to apply:** when 4.0 is released, re-diff the release against the audit (`.github/audits/gamdl-v4.0-preview-audit.md`), work through its follow-up list (lyrics `.ttml`, artwork, progress, PlayReady extra, settings screen, docs), test on real machines, then add 4.0 to the tested window in `tool-versions.toml` (which makes it the routine install). Do not do that on code reading alone.

# MeedyaDL - Claude Code Project Context

## Project Overview

A multiplatform media downloader desktop application built with **Tauri 2.0 + React + TypeScript**. Currently supports Apple Music via [GAMDL](https://github.com/glomatico/gamdl), with planned support for additional services. Targets macOS (Apple Silicon), Windows (x64/ARM64), Linux (x64/ARM64/ARMv7), and ChromeOS (via Linux `.deb`).

## Architecture

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS v4 + Zustand state management
- **Backend**: Rust (Tauri 2.0) with IPC command handlers
- **GAMDL Integration**: CLI subprocess calls (`python -m gamdl ...`) - never imported as a Python library
- **Multi-service architecture** (#107): Service-agnostic download pipeline with pluggable engines. `MediaServiceId` enum (Apple Music, YouTube Music, YouTube, Spotify, BBC iPlayer) detected from URLs. `engines.toml` defines engine metadata and per-platform engine chains (compiled into binary via `include_str!()`). `EngineRegistry` in `engine_registry.rs` provides runtime query layer (`resolve_engine()`, `resolve_engine_chain()`, `detect_platform()`). `EngineCommandBuilder` trait + `run_engine()` in `engine_runner.rs` abstract subprocess spawning with dual event emission ("engine-output" + legacy "gamdl-output"). Download queue items carry `service` and `engine` fields; enrichment pipeline guarded behind `is_apple_music` check. `PerServiceSettings` in `settings.rs` nests per-service config (Apple Music, Spotify stub, YouTube stub) with `engine_priority` overrides per platform. Engine fallback via `try_engine_fallback()` for platforms with multiple engines (e.g., BBC iPlayer: get_iplayer → yt-dlp). Frontend: `detectService()` and `parseMediaUrl()` in `url-parser.ts`, `getEngineConfig()` IPC, TypeScript types for all service settings.
- **Dependencies**: Self-contained in app data dir (Python via python-build-standalone, GAMDL via pip, tools)
- **Theming**: Platform-adaptive CSS custom properties (macOS/Windows/Linux themes)
- **Error Handling**: ErrorBoundary in main.tsx catches React crashes; unhandled rejection handler logs async errors. All frontend errors are persisted to Rust crash reports via `log_frontend_error` IPC command.
- **Logging**: `tracing` ecosystem (replaces `env_logger`) with dual output: stderr + daily-rotating file in `{app_data_dir}/logs/`. Compatible with `log` facade -- all `log::*!()` macros work unchanged.
- **Error Reports**: JSON files in `{app_data_dir}/crashes/`. Captures Rust panics (`setup_panic_handler()`), frontend errors (IPC), and download errors (terminal failures after all fallbacks/retries exhausted — network-category errors are excluded since they indicate connectivity issues, not app bugs). Auto-cleanup of reports older than 30 days. Users can report errors to GitHub Issues via `build_github_issue_url()` in `crash_report_service.rs` -- constructs a pre-filled issue URL with percent-encoded data, opened in the system browser. Title prefix and labels adapt to source type (`[Crash Report]` + `crash-report` label for panics/frontend errors; `[Error Report]` + `error-report` label for download errors). Privacy-first: `CrashReportDialog` shows a consent modal before submission. Backtrace truncated at 3500 chars for URL length safety. Issue template at `.github/ISSUE_TEMPLATE/crash-report.yml`.
- **Pre-download checks**: Three gates in `DownloadForm.tsx` before queueing: (1) Internet connectivity check (`check_internet_before_download` — multi-provider, multi-tier probe. Tier 1 (general internet): Cloudflare `1.1.1.1` → Google `google.com` (provider-neutral, sequential — first success short-circuits). Tier 2 (service-specific, only if Tier 1 passes): Apple Music API `amp-api.music.apple.com`. Three outcomes: Tier 1 fails = general "no internet" warning, Tier 1 passes but Tier 2 fails = "Apple Music API unreachable (internet is working)" warning, both pass = no warning) — if offline, the download is still queued but auto-start is skipped via `skip_auto_start` param on `start_download`, and a warning toast is shown; (2) Output path writability check (`check_output_path_before_download` — probes write access via temp file creation with 5s timeout) — **blocking**: prevents queueing if output path is inaccessible (catches disconnected cloud mounts, full disks, permission issues). Uses `spawn_blocking` + `tokio::time::timeout` to avoid hanging on unresponsive FUSE mounts. OS-specific error messages for ETIMEDOUT (errno 60, CloudMounter), ENOSPC, EROFS, ESTALE; (3) Cookie validation (`check_cookies_before_download`) — blocks if cookies expired/missing (skipped when offline). Cookie check is also skipped for wrapper users. Queue pre-flight also runs the output path check alongside internet/wrapper/cookie checks.
- **Toast deduplication**: Toasts with the same `message` are not duplicated on screen. Keyed toasts (optional `key` field) support category-based replacement and programmatic dismissal via `removeToastsByKey()`. Preflight warnings use keyed toasts with `preflight-cleared` events for auto-dismissal when checks pass.
- **Auto-retry without wrapper**: `auto_retry_without_wrapper` setting (default: `false`). When enabled and a wrapper download fails terminally, the queue automatically re-queues the item with wrapper disabled (cookie-based auth). Toggle in Settings > Advanced > Wrapper section (only visible when `use_wrapper` is true). Logic in `download_queue.rs` in both the `Err` path (non-zero exit) and success-path terminal (exit 0, no output) calls `retry_without_wrapper()` and re-processes the queue. Comprehensive `log::debug!()` tracing shows wrapper URL, setting value, item state, and retry result.
- **Wrapper m3u8 address** (GAMDL v3.1+, #605): `wrapper_m3u8_ip` setting (default: `"127.0.0.1:20020"`). When `use_wrapper=true` on GAMDL v3.1+, GAMDL no longer reads the HLS master playlist URL from Apple's API response — it opens a TCP connection to this address and receives the m3u8 URL from the wrapper service. Emission is double-gated: (a) `settings.use_wrapper == true`, (b) `gamdl_capabilities::supports(GamdlFeature::WrapperM3u8Ip)` returns `true` (i.e., the detected GAMDL release is 3.1+). Lives in both CLI (`--wrapper-m3u8-ip`) and INI (`wrapper_m3u8_ip`). Preflight check `check_wrapper_m3u8_health()` in `health_check_service.rs` does a 3-second TCP connect to the configured `host:port` before download, emitting a `PreflightCheck::WrapperM3u8` warning toast on failure. Configurable in Settings > Advanced > Wrapper (only visible when `use_wrapper` is true).
- **Network retry logging**: `try_network_retry()` returns `Option<(u32, u32)>` — the current attempt number and total attempts (initial + retries). Activity log differentiates error source: "Network error (via wrapper) — retrying (attempt {n} of {total})" vs "Network error (direct to Apple Music) — retrying (attempt {n} of {total})". Wrapper URL is surfaced in the activity log on network errors ("Network error occurred while using wrapper at {url}"). Default: 4 retries (5 total attempts).
- **I/O error handling**: Filesystem errors (disconnected cloud mounts, full disks, stale NFS handles) get a dedicated `"io"` match arm in the error handler with an actionable activity log message: "Filesystem error — check that the output directory is accessible and writable: {error_msg}". Detected by `is_io_error()` which matches `[Errno 60]` (macOS ETIMEDOUT), ENOSPC, EROFS, ESTALE, and generic I/O keywords. Not retried — user must fix the underlying issue.
- **Activity Log + Progress Bar refactor (Phase 3.5, #714)**: Six-commit holistic refactor landed in v1.0.1 prep. `services/progress_stages.rs` is the **single source of truth** for the 8 ordered per-item processing stages (`ProgressStage::{Metadata, WordLyrics, LyricsConversion, AnimatedArtwork, AcoustId, ReplayGain, MusicVideoDiscovery, Finalising}` — each with `weight()` + `label()`, covered by 6 unit tests for monotonicity / ellipsis convention / `ALL`-array completeness). Replaces the previous 8 scattered `PROGRESS_*_STAGE: f32` constants. Two shared helpers `set_stage(app, queue, dl_id, stage)` and `set_stage_with_label(app, queue, dl_id, stage, custom_label)` are callable from **both** the enrichment task AND the companion task, fixing the pre-3.5d bug where the closure-local `set_label` left the per-item bar caption stale on "ReplayGain loudness analysis…" while companion lyrics conversion ran for 30+ minutes (#712). Sub-stage labels now exist for lyrics format conversion (Enhanced LRC / WebVTT / Rich SRT / ASS / subtitle embed), MusicBrainz lookup, manifest write, content-rating rename, artist promo video, and the per-tier companion download phases. The 4 emission helpers (`emit_download_log`, `emit_app_log`, `emit_verbose_download_log`, `emit_verbose_app_log`) collapsed to facades over a shared `emit_inner` (Phase 3.5c) so future emission rules touch one place. New `emit_subprocess_line(app, dl_id, stream, line, show_in_ui)` helper centralised the four direct `app.emit("activity-log", …)` sites (Phase 3.5e). New `process::humanise_codec_skip_line()` (Phase 3.5h) strips GAMDL's noisy `(media ID: NNN)` and Python-repr codec list from "Skipping … format is not available" lines before activity-log emission. Companion task now snapshots the audio-file count BEFORE running GAMDL and emits "no compatible format available — skipped" instead of "Companion download complete" when zero new files landed (Phase 3.5h, prevented misleading "complete" messages when GAMDL exits 0 but skipped every track). Frontend caption assembly extracted to `lib/progress-caption.ts::formatActiveItemCaption()` (Phase 3.5f) so caption rules are unit-testable in isolation.
- **Library Scan page** (Phase 5a, #717): New `library` page in the AppPage union, sidebar nav between Queue and History, component at `src/components/library/LibraryScanPage.tsx`. Wraps the existing `scan_folder_for_manifests` IPC (#456) in a first-class UI: folder picker → scan → results table with Artist / Album / track count / on-disk file count / detected codec / last-download date. Foundation for the gap-fill UX tracked in #717: smart-retry diff per row (5b), Apple Music `lastModifiedDate` compare (5c), MV gap-fill modal with two prompt branches (5d), per-item `music_video_companion_override` on QueueItem (5e), "Re-download gaps" action (5f). All five sub-features land as separate PRs after v1.0.1 stable to keep each user-visible piece reviewable.
- **Activity Log**: App-wide via shared `utils/activity_log.rs` module. Two emission helpers: `emit_download_log(app, download_id, message)` for per-download events, `emit_app_log(app, message)` for system-level events (uses `download_id: "system"` sentinel). Frontend renders `[System]` badge in `text-status-info` colour for system entries. Covers: update checks, dependency installs, cookie imports, settings saves, queue operations (enqueue/cancel/retry/clear/export/import), login window, pre-flight checks, app startup, and queue recovery. The `ActivityLogEvent` struct and helpers were refactored from `download_queue.rs` private scope to shared utility for cross-module use. **Capped at 10,000 entries** (`MAX_ENTRIES` in `activityStore.ts`) — when exceeded, oldest entries are trimmed. Entries have auto-incrementing `_id` for stable React keys. **Virtualized rendering** via `@tanstack/react-virtual` — only ~150 DOM nodes rendered regardless of entry count (previously rendered all entries, causing 14+ GB WebView RAM at 7,500 entries). **RAF-batched event ingestion**: `App.tsx` buffers incoming `activity-log` events and flushes them in a single `addEntries()` call per animation frame (~60/s max store updates vs hundreds/s previously). **Backend `\r` coalescing**: `download_queue.rs` stdout/stderr readers only emit the last `\r`-separated segment to `activity-log` (5-10x event reduction for progress-heavy downloads); **verbose mode bypasses `\r` coalescing** so all progress lines are emitted when `verbose_activity_log` is enabled. Track separator lines include artist and album context from the queue item. Queue item demarcation: separator line emitted at start of each download. Export filename: `MeedyaDL-activity-log_YYYY-MM-DD_HHhMMm.log` (`.log` extension, timestamped).
- **Persistent on-disk activity log** (#541): `services/activity_log_writer.rs` streams every `ActivityLogEvent` to `{log_dir}/activity-YYYY-MM-DD.log` via a buffered Tokio background task. `start(log_dir, shutdown)` spawns the writer and returns an `ActivityLogWriterHandle` that wraps `UnboundedSender<ActivityLogEvent>`; `utils::activity_log::register_disk_writer()` stores the handle in a `OnceLock` so `emit_download_log`, `emit_app_log`, `emit_verbose_download_log`, and `emit_verbose_app_log` all fan out to disk after emitting the Tauri event. The four direct-emit sites in `download_queue.rs` (`emit_companion_stream_line`, stdout/stderr readers, track separator) call `write_to_disk(&event)` alongside their `app.emit("activity-log", &event)`. **Verbose events are written to disk even when the UI is filtering them** — the file is the forensic record. Writer task uses `tokio::select!` over `rx.recv()` and a 500 ms flush tick, polls the shared `ShutdownSignal` to flush-and-exit cleanly, and detects UTC date rollover at write time. Unit tests (`activity_log_writer::tests`) cover file creation, line format, rollover, and `list_log_files()` ordering. Retention 7 days via `clear_old_logs()` in `lib.rs` (which also scans the override dir when set). IPC in `commands/activity_log.rs`: `export_disk_activity_log(days_back)` (native save dialog, default 3 days, concatenates newest-first files in chronological order with header banners) and `get_logs_folder_path()` (returns active dir, creating if absent — frontend pairs with `@tauri-apps/plugin-shell`'s `open()` to reveal). Frontend: **Export Disk** + **Reveal** buttons in `ActivityLog.tsx` header; existing in-memory **Export** preserved. User-configurable location via `activity_log_path_override: String` setting (default empty = `{app_data_dir}/logs/`). `lib.rs::resolve_activity_log_dir()` tries `create_dir_all` on the override and falls back to default with `log::warn!` on failure. UI: Browse + Reset buttons in Settings > Advanced > Diagnostics; applies on next app restart (writer owns the file handle for the process lifetime). `ShutdownSignal::flag()` exposes the inner `Arc<AtomicBool>` so the writer can poll shutdown without holding a Tauri `State`.
- **Error classification**: `process::classify_error()` returns category strings used for retry strategy and UI display. Categories: `auth`, `io`, `network`, `codec`, `not_found`, `rate_limit`, `tool`, `unknown`. Network detection covers: "network", "timeout", "timed out", "connection", "connecterror", "dns", "httpx", "httpcore". The httpx/httpcore keywords catch any error from Python's HTTP transport libraries (including raw traceback frames containing these library paths).
- **Error extraction**: In `download_queue.rs`, `extract_python_exception()` is ALWAYS tried against raw stderr (not just when `errors.last()` contains "traceback"). This handles cases where the output parser captures a traceback frame as the last error instead of the actual exception. The output parser's Priority 7 keyword matching skips lines starting with `File "` (Python traceback frames) to prevent function names like `map_httpcore_exceptions` from triggering the "exception" keyword.
- **Sentry** (opt-in): `sentry_enabled` setting (default: `false`). When enabled, Rust SDK + JS SDK send anonymous crash data. Toggle in Settings > Advanced. Exists as a parallel path alongside the GitHub Issues reporting.
- **Cancellation handling**: When a download is cancelled, the error handler short-circuits on the sentinel string `"Download cancelled by user"` — it only decrements `active_count` without overwriting the already-set `Cancelled` state or creating an error report.
- **URL validation**: URLs are validated as starting with `http://` or `https://` before being passed to GAMDL subprocess in `gamdl_service.rs`. Prevents `--`-prefixed strings from being misinterpreted as CLI flags.
- **Credential redaction**: `redact_url_query()` strips query parameters from wrapper URLs before logging, preventing authentication tokens from persisting in plaintext log files.
- **Timeout safety**: All HTTP clients use explicit timeouts — `download_file()` uses 30s connect timeout, health check uses 5s, GitHub API uses 15s, `pip show gamdl` uses 10s. Prevents indefinite blocking on unresponsive servers or network mounts.
- **Log retention**: Tracing logs cleaned up after 7 days, session logs (trimmed activity entries) after 30 days, by `clear_old_logs()` at startup. Session logs preserve debugging data from trimmed in-memory entries via `save_session_log` IPC command.
- **IPC rate limiting**: Sliding-window rate limiter in `utils/rate_limiter.rs` applied to `start_download` (10/min), `check_all_updates` (1/min), `download_and_install_app_update` (1/min), `import_cookies_from_browser` (3/min).
- **Settings integrity**: SHA-256 checksum written to companion `settings.json.sha256` on save, verified on load. Mismatch logs warning but loads settings (backwards compatible).
- **Settings migration**: `settings_version` field with `migrate_settings()` in `config_service.rs`. Sequential migrations (v0→v1, etc.) run on load. `CURRENT_SETTINGS_VERSION` constant.
- **After-queue actions**: `AfterQueueAction` enum (do_nothing, open_output_folder, play_sound, close_meedyadl, restart_computer, hibernate_computer, shutdown_computer) with persistent + one-shot modes. Settings dropdown in General > Preferences, right-click context menu on Download page, status bar indicator.
- **Notification tiers**: Error/warning toasts are persistent (no auto-dismiss), info/success respect configurable `notification_auto_dismiss_seconds` (3-60s, default 5). Backend notification throttling batches rapid notifications of the same category (10s window). The duplicate-URL toast in `DownloadForm.tsx` uses `'info'` (auto-dismisses) rather than `'warning'` because the download is still queued and no user action is required (#657).
- **Native notification preflight** (#658): The Tauri `tauri-plugin-notification` JS API's `requestPermission()` only triggers the macOS system prompt the first time it is called for a bundle ID — if the user dismissed (rather than granted/denied) the original prompt, every subsequent call resolves silently with `'default'` and `sendNotification()` becomes a no-op. To work around this, `App.tsx` Effect 2 runs a one-shot `isPermissionGranted` → `requestPermission` preflight after settings load, *unless* `notification_style == 'in_app_only'`. The result is logged to the WebView console (`[notification] startup permission request resolved: …`). The `addToast` notification path in `uiStore.ts` no longer swallows errors silently — failures are surfaced as `console.warn`. A "Send Test Notification" button in Settings > General > Notifications lets users verify the OS pipeline on demand. Backend `send_desktop_notification` in `download_queue.rs` also gates on `notification_style != "in_app_only"` so the user's preference is honoured by the Rust completion path too (previously it only checked `desktop_notifications: bool`).
- **Fallback chain UI — remove + re-add** (#659): `FallbackChainList<T>` accepts an optional `allItems: readonly T[]` prop. When supplied, each row gets an `X` (remove) button and an "Available (not in chain)" panel renders below the active list with `+` (re-add) buttons. The remove button on the only remaining row is disabled — an empty chain would block every download. No settings schema migration is needed: the chain remains a `Vec<SongCodec>` / `Vec<VideoResolution>`; removed items are simply absent from the array. `merge_options()` and `try_fallback()` already handle arbitrary chain lengths. `FallbackTab.tsx` builds the universe via `Object.keys(SONG_CODEC_LABELS) as SongCodec[]` (and the analogous `VIDEO_RESOLUTION_LABELS`) into module-level `ALL_SONG_CODECS` / `ALL_VIDEO_RESOLUTIONS` constants. `QualityTab` callers (artist auto-select, video codec priority) intentionally do NOT pass `allItems` and continue to render as pure-reorder lists.
- **Python traceback noise suppression** (#660): GAMDL and its Python deps (`httpx`, `async_lru`, `gamdl.interface`) raise multi-line tracebacks on certain code paths (notably music-video cover-art fetch). The activity log used to render two red Error entries per traceback — the `Traceback (most recent call last):` header (matched by Priority 7's `traceback` keyword) and the exception summary line (matched by `PYTHON_EXCEPTION_REGEX`). The header was duplicate noise; multiplied across many retries it produced 40+ lines for a single recurring upstream bug. Fix layered three ways: (a) new `GamdlOutputEvent::TracebackFrame { raw: String }` variant captures the header, `File "..."` stack frames, and caret highlight lines explicitly; (b) the `traceback` keyword is removed from Priority 7 — the explicit variant supersedes it; (c) new `process::is_python_traceback_noise(line)` helper (cheap, no-regex twin of the Priority 3c branch) is called by the stdout/stderr readers in `download_queue.rs` to gate the per-line `activity-log` Tauri event in non-verbose mode. The on-disk activity-log writer still records every line (forensic record). The actual exception summary (`TypeError: …`, `httpx.ConnectError: …`) remains a real Error event and is unaffected.
- **Terminal-state guards** (#661): `set_complete()` and `set_error()` on `DownloadQueue` refuse to overwrite terminal states. `set_complete` skips when state is `Error` or `Cancelled`; `set_error` skips when state is `Complete` or `Cancelled`. Without these guards, the per-item completion task at the bottom of `process_queue()` would always call `set_complete` after the post-companion advisory pass, silently flipping a previously-failed item back to `Complete` in the UI ("revival"). Likewise, late-arriving subprocess errors during cancellation teardown could overwrite `Cancelled → Error` and poison the error field. Skipped transitions emit a `log::debug!`. Tests: `set_complete_does_not_revive_errored_item`, `set_complete_does_not_revive_cancelled_item`, `set_error_does_not_overwrite_cancelled_item`, `set_error_does_not_overwrite_complete_item` in `download_queue::tests`. Companion-timeout activity-log message also corrected from the misleading `"marking complete"` to `"skipping remaining companions; final tag pass still to run"`, and a new `Final tag pass: applying [Explicit]/[Clean] suffixes…` log entry fires at the start of the post-companion advisory pass so the long silent gap becomes visible.
- **Cooperative-cancel for sync companion code** (#663): `tokio::task::JoinHandle::abort()` only takes effect at an `.await` point — it cannot preempt a synchronous function. The companion task's `run_companion_lyrics_conversion` (sync `fn`, recursive `find_dirs_with_ttml` walk + per-album-dir TTML→LRC/SRT/VTT/ASS conversion) used to keep emitting `Companion: converted N TTML file(s) to Enhanced LRC` activity-log events for 5–15 minutes *after* the deadline timeout fired and `handle.abort()` was called — the user-visible "spring back to life" symptom on items already marked Complete. Fix: `spawn_companion_downloads` now returns a `CompanionTaskHandle { handle: JoinHandle, aborted: Arc<AtomicBool> }`. The completion task's deadline path calls `handle.abort()` (the wrapper method, which sets the flag *and* aborts the runtime task) before awaiting `handle.handle`. The companion tier loop checks the flag between iterations (so we don't launch another GAMDL after timeout); `run_companion_lyrics_conversion` checks it on entry and between every album_dir iteration in the conversion loop. When the flag fires, a single `Companion task aborted — skipping remaining post-processing` line is emitted and the function returns. **Pattern to remember**: any new sync function called from inside an async tokio task must accept and check an `Arc<AtomicBool>` cooperative-cancel flag if it can take longer than the parent task's expected lifetime.
- **BPM analysis**: `bpm_service.rs` with two-phase approach (#418): (1) checks existing BPM tags via ffprobe, (2) if absent, analyses audio via FFmpeg `silencedetect` filter (`aresample=22050,lowpass=f=300,highpass=f=40,silencedetect=noise=-30dB:d=0.1`) for onset detection. Writes to M4A (`tmpo` atom), FLAC (`BPM` Vorbis Comment), MP3 (`TBPM` ID3v2 frame). Full DSP analysis deferred to MeedyaSuite-core `meedya-audio-analysis` module. `bpm_analysis_enabled` setting (default: false).
- **Disk space check**: `check_output_path()` preflight now checks available space via `fs2::available_space()`. Warns if < 500 MB remaining.
- **macOS updater artifact naming**: Tauri 2.x names the macOS updater bundle `MeedyaDL.app.tar.gz` (after the `.app` bundle, no arch/version suffix). The `release.yml` upload step and `latest.json` rebuild must use this exact filename. The `fix-updater-manifest.yml` standalone workflow uses the same filename. Previous incorrect filename `MeedyaDL_aarch64.app.tar.gz` caused `darwin-aarch64` to be missing from `latest.json`, breaking macOS in-app updates (#368).
- **CI hardening**: `workflow_dispatch` inputs in `release.yml` and `version-bump.yml` are passed via `env:` variables, not direct `${{ }}` shell interpolation, preventing injection attacks from collaborators. All release-critical GitHub Actions are pinned to immutable commit SHAs (not mutable version tags like `@v4`) across all 5 workflow files — prevents supply chain attacks where a compromised action tag could inject malicious code into CI/CD pipelines. `cargo-deny` licence scanning via `deny.toml` runs in the CI backend job to enforce a permissive licence allowlist. CodeQL workflow requires `actions: read` permission alongside `security-events: write` and `contents: read` for the analyze job to access workflow run telemetry.
- **INI injection prevention**: `sanitize_ini_value()` in `config_service.rs` strips `\n` and `\r` from all user-provided string values before writing to GAMDL's config.ini. Prevents INI key injection via crafted settings import files.
- **HTML sanitization**: `rehype-sanitize` in `HelpViewer.tsx` strips dangerous HTML elements (script, iframe, event handlers) while allowing safe ones (details, summary) via a custom allowlist schema.
- **Import validation**: `sanitize_imported_settings()` in `commands/settings.rs` truncates paths (1024), URLs (2048), templates (512), language (20), storefront (10), and strips control characters from all imported fields.
- **Atomic file writes**: Both `settings.json` and `queue.json` use write-to-temp-then-rename pattern (`std::fs::write` to `.json.tmp`, then `std::fs::rename`) for crash/power-loss safety.
- **Queue debounce**: `save_queue_to_disk()` saves at most once per 500ms via `AtomicU64` timestamp, with a delayed follow-up save to ensure final state is persisted. Reduces I/O pressure from rapid queue mutations.
- **No shell interpolation**: All subprocess calls use parameterised `Command::new().arg()` — no `sh -c format!()` patterns. The two former `sh -c` invocations in `dependency_manager.rs` (GPAC cpio extraction and .deb tar extraction) were replaced with direct process invocations.
- **Modal focus trap**: `Modal.tsx` has `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, Tab/Shift+Tab focus cycling, auto-focus on open, and focus restore on close.
- **SECURITY.md**: Vulnerability reporting policy with responsible disclosure instructions, supported versions, and comprehensive security measures list.
- **Premium feature token resolution**: `TokenSource` enum in `apple_music_api.rs` with 3-tier priority for features that need a developer token (syllable-lyrics, animated artwork, music video relations): (1) User-provided MusicKit credentials (`UserProvided`), (2) Compile-time embedded token (`option_env!("APPLE_DEVELOPER_TOKEN")`) (`Embedded`), (3) Web player-extracted token from OS keychain (`WebPlayer`). `resolve_premium_feature_token()` returns `Option<(String, TokenSource)>`. The web player token is opportunistically extracted during Apple Music login via `login_window_service.rs` — JavaScript evaluation on the WebView captures the `MusicKit.getInstance().developerToken` value, which is then stored in the OS keychain (`webplayer_developer_token` key) via `keyring` crate. Token is NOT used for basic catalog API calls (those always use user-provided MusicKit JWT); only for premium features as a last-resort fallback. IPC commands: `has_webplayer_token` (checks keychain), `clear_webplayer_token` (removes from keychain) in `commands/credentials.rs`.
- **Dev access mode**: Hidden developer tools activation via Konami code sequence (arrow keys + BA) in the frontend. `useKonamiCode.ts` hook listens for the key sequence and triggers a passphrase modal. Passphrase validated via SHA-256 hash comparison (hash stored in code, never the plaintext). On successful activation: sets `dev_access_enabled: bool` in AppSettings + writes a keychain sentinel (`dev_access_sentinel` key). `check_dev_access` IPC reads the keychain sentinel (survives settings reset). `activate_dev_access` / `deactivate_dev_access` IPC commands toggle both settings and keychain. Gates a "Developer Tools" section in `AdvancedTab.tsx` (`DevToolsSection` component) showing: web player token status (present/absent + clear button), token source hierarchy visualization, and diagnostic info. Section only renders when `dev_access_enabled` is true.
- **Regex caching**: `parse_apple_music_url()` in `apple_music_api.rs` uses `static LazyLock<Regex>` for one-time compilation instead of per-call `Regex::new().expect()`.
- **SHA-256 checksum verification**: `download_file()` in `archive.rs` computes SHA-256 during streaming download (zero extra I/O pass) using the `sha2` crate. - **Serial queue processing** (#455 / #706): Queue processes one item at a time — the ENTIRE pipeline (GAMDL download → companions → enrichment → lyrics → manifest) completes before the next item starts. Two mechanisms enforce this together: (a) the `process_queue()` cascade lives inside the completion task so a follow-up item is *requested* only after the current one finishes (#455); (b) the queue *slot* (`active_count`) is held throughout post-processing — `q.on_task_finished()` is called at the bottom of the completion task (right after `set_complete`), not at primary GAMDL exit, so any concurrent `process_queue` invocation (user IPC, fallback retry, startup recovery) sees `active_count == max_concurrent` and is blocked from grabbing the next item early (#706 — pre-fix the slot decremented at line 6246 and items legitimately ran in parallel during post-processing). The completion task takes ownership of an `ActiveSlotGuard` RAII guard at spawn; if the task panics or is aborted before the explicit release, the guard's `Drop` fires a fire-and-forget `tokio::spawn` to release the slot, preventing a permanent queue stall. Happy path calls `guard.disarm()` after the explicit `q.on_task_finished()` so Drop is a no-op. Completion task has a scaled timeout: `compute_completion_timeout(track_count)` for the enrichment branch (10 min base + 10 s/track, capped at 4 h, #461 / #579), and `compute_companion_timeout(track_count, tier_count)` for the companion-wait branch (enrichment budget + 8 min/tier, same cap, #705) — multi-tier modes (e.g. Atmos→all formats = 4 full GAMDL re-downloads) need the per-tier headroom. Soft timeout warns and waits a second deadline before hard-aborting via `CompanionTaskHandle::abort()`. Hard / soft / enrichment activity-log messages identify the affected item via `format_content_label(&QueueItemStatus)` (Artist — Album — Track, URL fallback). `set_complete()` clears `processing_label`, `speed`, and `eta` fields (#416).

- **Fallback quality chains**: Version-aware strategy with safety net. For GAMDL >= 2.9.1: first attempt uses native `--song-codec-priority` flag to pass the entire fallback chain (e.g., `atmos,alac,aac,...`) in a single process invocation. If native priority fails, MeedyaDL's own `try_fallback` system kicks in as a safety net, retrying each codec individually via `--song-codec-priority <single-codec>`. For GAMDL < 2.9.1: MeedyaDL's `try_fallback` is the only mechanism. `try_fallback()` returns `Option<(GamdlOptions, usize, usize)>` — the new options, 1-indexed fallback position, and chain length. Activity log shows: "Format not available — trying {codec} (fallback {n} of {total})". Music chain: ALAC→Atmos→AC3→AacBinaural→Aac→AacLegacy; Video: 2160p→...→240p. Config.ini dual-key strategy writes both `song_codec` (for < 2.9.1) and `song_codec_priority` (for >= 2.9.1) to ensure compatibility across GAMDL versions. **Gap-fill retry**: When native priority partially succeeds (some tracks downloaded, some skipped due to experimental codecs without wrapper), MeedyaDL automatically re-runs GAMDL with `overwrite=false` and a filtered priority chain excluding wrapper-dependent codecs (Atmos, AC3). This fills gaps with lossless/lossy fallbacks without overwriting successful experimental-codec downloads. Helpers: `count_codec_skip_warnings()`, `build_gapfill_priority_chain()`, `count_audio_files_in_directory()`. `SongCodec::is_wrapper_dependent()` identifies codecs requiring wrapper auth. `SongCodec::from_cli_string()` parses CLI strings back to enum variants.
- **Apple Music URL support**: Three domains accepted: `music.apple.com` (standard), `classical.apple.com` (Apple Music Classical), and `itunes.apple.com` (legacy). Validated in both the frontend URL parser (`src/lib/url-parser.ts`) and backend regex patterns in the Rust services. All five `parse_apple_music_url` entity regexes in `apple_music_api.rs` alternate `(?:classical|music|itunes)` consistently (album, song, music-video, artist, catalog playlist) so iTunes URLs ride the same metadata-prefetch and storefront-normalisation rails as the other two domains (#548). **Non-geographic URLs** (missing storefront code, e.g., `music.apple.com/album/...`) are auto-normalized at enqueue time by injecting a storefront based on OS locale (or `"us"` fallback) via `normalize_apple_music_url()` in `apple_music_api.rs`. GAMDL requires the storefront for its URL regex but ignores it for API calls (uses cookies/wrapper auth). Enrichment API calls use `fetch_album_metadata_with_fallback()` which retries with alternative storefronts (OS locale, `"us"`) when the primary returns 404 — handles region mismatches from shared links. **Personal library URLs** (`/library/albums/l.XXXX`, `/library/songs/...`) are accepted as `'library'` content type by the frontend URL parser and passed through to GAMDL as-is.
- **URL audit diagnostics (#487 umbrella — #546/#547/#548/#549)**: `start_download` in `commands/gamdl.rs` emits classification logs for four URL classes with known quirks, so downstream filename-path behaviour can be correlated without replaying the download. (a) `/library/` URLs log at INFO noting no MeedyaDL safety net applies (#546). (b) `classical.apple.com` URLs log at INFO noting shared templates with `music.apple.com` and the movement-title collision risk when album context is lost (#547). (c) `itunes.apple.com` URLs log at WARN — the parser regex gap is closed but GAMDL's own URL-regex compatibility with the legacy domain is still unverified (#548). (d) Any URL that passes the host allowlist but returns `None` from `parse_apple_music_url` after normalisation (and isn't a library URL) logs at WARN as "Unrecognised Apple Music URL shape" — catches uploaded / post / novel path variants without hard-coding specific substrings (#549). All four diagnostics fire via both `log::*!` and `emit_app_log` so the signal lands in the tracing log file and the in-app activity log.

## Release Workflow

```text
Push fix:/feat: commits directly to main
  → release-please creates/updates a Release PR (bumps versions)
  → User reviews and merges the Release PR
  → release-please creates tag (e.g., v0.3.0) using RELEASE_PAT
  → release.yml triggers → 6 platform builds → draft GitHub Release
  → changelog.yml triggers → git-cliff regenerates CHANGELOG.md
```

Manual override: `version-bump.yml` + `scripts/bump-version.mjs` for non-standard releases.

### Release Channels (current state)

`UpdateChannel` enum in `models/settings.rs` declares **seven** ordered variants — `Nightly < Weekly < Monthly < Alpha < Beta < Rc < Stable` (`PartialOrd`) — and all seven now have producer-side automation: nightly / weekly / monthly are cron-driven; alpha / beta / release-candidate are push-driven on each respective long-lived branch; stable comes from release-please-action (or version-bump.yml for manual hotfixes).

Long-lived channel branches (force-push-protected): `nightly`, `weekly`, `monthly`, `alpha`, `beta`, `release-candidate`. Stable is `main`. Branch protection lives in two split rulesets — `.github/rulesets/protected-stable-branches.json` (main / release-candidate / beta / alpha — no bypass actor, fast-forward only) and `.github/rulesets/protected-cron-channels.json` (nightly / weekly / monthly with admin-bypass for cron pushes). Both are applied by `apply-branch-rulesets.yml`. `auto-delete-merged-branches.yml` exempts the channel names from PR-merge cleanup.

- `nightly-release.yml` — cron `0 0 * * *`. Resets `nightly` to `main`, merges every `origin/feat/*` (skips conflicts, opens issue), bumps version to `X.Y.Z-nightly.YYYYMMDD` across package.json / tauri.conf.json / Cargo.toml, force-pushes `nightly`, creates tag → triggers `release.yml`.
- `weekly-release.yml` — cron `0 0 * * 0` (every Sunday at 00:00 UTC). Identical pipeline shape to nightly-release.yml; tag suffix is `-weekly.YYYYMMDD`. Concurrency group `weekly-release`. Conflict-issue label is `weekly-conflict`.
- `monthly-release.yml` — cron `0 0 1 * *` (1st of each month at 00:00 UTC). Identical pipeline shape to nightly-release.yml; tag suffix is `-monthly.YYYYMMDD`. Concurrency group `monthly-release`. Conflict-issue label is `monthly-conflict`.
- `alpha-release.yml`, `beta-release.yml`, `release-candidate-release.yml` — push-driven (no cron). Triggered on every push to the matching long-lived branch. Each computes a monotonic counter across all existing tags of its channel (`vX.Y.Z-alpha.N` / `-beta.N` / `-rc.N`), bumps version manifests, commits, and pushes the tag — which triggers `release.yml`. Counters never reset across base-version bumps. Concurrency: per-branch lock prevents two pushes from racing into the same `N`.
- `release.yml` — derives the `prerelease` flag from the tag suffix at runtime (`prerelease: contains(tag, '-')`). Builds for any tag matching `v*`. **Auto-publishes prerelease drafts** at the end of `finalize-release` (#646); stable drafts stay as drafts pending maintainer review (`release-please-action` publishes them on the standard path; `version-bump.yml` pre-creates the release object via #645 to avoid the platform-job fragmentation that affected v0.49.1 / v0.49.2).
- `realign-alpha.yml` — one-shot helper to fast-forward `alpha` back onto `main` after a stable cut.
- `update-security-policy.yml` — runs on push to main and on tag push. Rewrites the "Supported Versions" table in SECURITY.md between sentinel comments, so the policy file always reflects the latest released version (currently v0.49.2).
- `check_all_updates` filters GitHub releases by `user_channel`. A Stable user hits `releases/latest`; non-Stable channels hit `releases?per_page=20` and pick the newest entry whose channel is `>=` the user's selected channel (so a user on Beta sees Beta, RC, and Stable — channel promotion, not exact-match).
- `download_and_install_app_update` in `commands/updates.rs` refuses tags whose channel is `< user_channel`. Even a tampered manifest or stale deep link can't downgrade stability.
- Channel-bump UI in `GeneralTab.tsx` gates Nightly/Weekly/Monthly/Alpha behind `dev_access_enabled` (Konami sentinel). `ChannelSwitchWarning.tsx` prompts on switch to a pre-release channel.
- Legacy `check_pre_releases: bool` is implicitly enabled whenever `update_channel != Stable`.

### Conserving GitHub Actions Minutes

All workflows (CI, Changelog, Release Please, Release, Nightly Release, Apply Branch Rulesets) support both automatic triggers and manual `workflow_dispatch`.

**Do NOT use `[skip ci]`** in commit messages unless the user explicitly requests it. Every push must trigger CI to validate changes. Manual triggering is available if needed:

```bash
gh workflow run "CI" --ref main
gh workflow run "Release Please" --ref main
gh workflow run "Changelog" --ref main
gh workflow run "Release" -f tag=v0.3.3             # Release requires a tag input
gh workflow run "Nightly Release" --ref main        # Optionally -f dry_run=true
gh workflow run "Apply Branch Rulesets" --ref main  # Re-applies protected-branch ruleset
```

Note: `workflow_dispatch` only shows a "Run workflow" button in the GitHub UI for workflows whose YAML is on the default branch. Until a new workflow is merged to `main`, trigger it via the CLI with an explicit `--ref`.

### Release Please Branch Naming

Release-please v4 creates PR branches with the format:
`release-please--branches--{target}--components--{component}`

For this project (component name from `package.json` `name` field):
`release-please--branches--main--components--meedyadl`

The `.release-please-manifest.json` must match the current version to avoid release-please trying to create releases from an old version.

## Important Notes

- Rust env: `export PATH="$HOME/.cargo/bin:$PATH"` (not `source "$HOME/.cargo/env"` — fails in zsh sandbox)
- Icons generated from `assets/icons/app-icon.svg` via `scripts/generate-icons.mjs` (requires `sharp` — install temporarily with `npm i sharp`)
- All settings stored as JSON in platform app data directory
- GAMDL config.ini is synced from GUI settings
- CSP in `tauri.conf.json` must include `connect-src ipc: http://ipc.localhost` for IPC
- Vite build config uses `TAURI_ENV_PLATFORM` for platform-specific JS targets (safari16.4 / chrome111)
- `devtools` Cargo feature enabled for WebView inspection in release builds
- **macOS codesign `--timestamp` workaround**: Tauri's `tauri-macos-sign` crate omits `--timestamp` from `codesign` calls, causing non-deterministic notarization failures ([tauri#11992](https://github.com/tauri-apps/tauri/issues/11992)). Both `release.yml` and `pre-release.yml` include a PATH-based wrapper script (Step 8.9) that intercepts `/usr/bin/codesign` and injects `--timestamp` automatically. Remove the wrapper once the upstream Tauri fix lands.

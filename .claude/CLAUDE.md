# MeedyaDL - Claude Code Project Context

## Project Overview

A multiplatform media downloader desktop application built with **Tauri 2.0 + React + TypeScript**. Currently supports Apple Music via [GAMDL](https://github.com/glomatico/gamdl), with planned support for additional services. Targets macOS (Apple Silicon), Windows (x64/ARM64), Linux (x64/ARM64/ARMv7), and ChromeOS (via Linux `.deb`).

## Architecture

- **Frontend**: React 19 + TypeScript + Vite + Tailwind CSS v4 + Zustand state management
- **Backend**: Rust (Tauri 2.0) with IPC command handlers
- **GAMDL Integration**: CLI subprocess calls (`python -m gamdl ...`) - never imported as a Python library
- **Dependencies**: Self-contained in app data dir (Python via python-build-standalone, GAMDL via pip, tools)
- **Theming**: Platform-adaptive CSS custom properties (macOS/Windows/Linux themes)
- **Error Handling**: ErrorBoundary in main.tsx catches React crashes; unhandled rejection handler logs async errors. All frontend errors are persisted to Rust crash reports via `log_frontend_error` IPC command.
- **Logging**: `tracing` ecosystem (replaces `env_logger`) with dual output: stderr + daily-rotating file in `{app_data_dir}/logs/`. Compatible with `log` facade -- all `log::*!()` macros work unchanged.
- **Error Reports**: JSON files in `{app_data_dir}/crashes/`. Captures Rust panics (`setup_panic_handler()`), frontend errors (IPC), and download errors (terminal failures after all fallbacks/retries exhausted — network-category errors are excluded since they indicate connectivity issues, not app bugs). Auto-cleanup of reports older than 30 days. Users can report errors to GitHub Issues via `build_github_issue_url()` in `crash_report_service.rs` -- constructs a pre-filled issue URL with percent-encoded data, opened in the system browser. Title prefix and labels adapt to source type (`[Crash Report]` + `crash-report` label for panics/frontend errors; `[Error Report]` + `error-report` label for download errors). Privacy-first: `CrashReportDialog` shows a consent modal before submission. Backtrace truncated at 3500 chars for URL length safety. Issue template at `.github/ISSUE_TEMPLATE/crash-report.yml`.
- **Pre-download checks**: Three gates in `DownloadForm.tsx` before queueing: (1) Internet connectivity check (`check_internet_before_download` — multi-provider, multi-tier probe. Tier 1 (general internet): Cloudflare `1.1.1.1` → Google `google.com` (provider-neutral, sequential — first success short-circuits). Tier 2 (service-specific, only if Tier 1 passes): Apple Music API `amp-api.music.apple.com`. Three outcomes: Tier 1 fails = general "no internet" warning, Tier 1 passes but Tier 2 fails = "Apple Music API unreachable (internet is working)" warning, both pass = no warning) — if offline, the download is still queued but auto-start is skipped via `skip_auto_start` param on `start_download`, and a warning toast is shown; (2) Output path writability check (`check_output_path_before_download` — probes write access via temp file creation with 5s timeout) — **blocking**: prevents queueing if output path is inaccessible (catches disconnected cloud mounts, full disks, permission issues). Uses `spawn_blocking` + `tokio::time::timeout` to avoid hanging on unresponsive FUSE mounts. OS-specific error messages for ETIMEDOUT (errno 60, CloudMounter), ENOSPC, EROFS, ESTALE; (3) Cookie validation (`check_cookies_before_download`) — blocks if cookies expired/missing (skipped when offline). Cookie check is also skipped for wrapper users. Queue pre-flight also runs the output path check alongside internet/wrapper/cookie checks.
- **Toast deduplication**: Toasts with the same `message` are not duplicated on screen. Keyed toasts (optional `key` field) support category-based replacement and programmatic dismissal via `removeToastsByKey()`. Preflight warnings use keyed toasts with `preflight-cleared` events for auto-dismissal when checks pass.
- **Auto-retry without wrapper**: `auto_retry_without_wrapper` setting (default: `false`). When enabled and a wrapper download fails terminally, the queue automatically re-queues the item with wrapper disabled (cookie-based auth). Toggle in Settings > Advanced > Wrapper section (only visible when `use_wrapper` is true). Logic in `download_queue.rs` in both the `Err` path (non-zero exit) and success-path terminal (exit 0, no output) calls `retry_without_wrapper()` and re-processes the queue. Comprehensive `log::debug!()` tracing shows wrapper URL, setting value, item state, and retry result.
- **Network retry logging**: `try_network_retry()` returns `Option<(u32, u32)>` — the current attempt number and total attempts (initial + retries). Activity log differentiates error source: "Network error (via wrapper) — retrying (attempt {n} of {total})" vs "Network error (direct to Apple Music) — retrying (attempt {n} of {total})". Wrapper URL is surfaced in the activity log on network errors ("Network error occurred while using wrapper at {url}"). Default: 4 retries (5 total attempts).
- **I/O error handling**: Filesystem errors (disconnected cloud mounts, full disks, stale NFS handles) get a dedicated `"io"` match arm in the error handler with an actionable activity log message: "Filesystem error — check that the output directory is accessible and writable: {error_msg}". Detected by `is_io_error()` which matches `[Errno 60]` (macOS ETIMEDOUT), ENOSPC, EROFS, ESTALE, and generic I/O keywords. Not retried — user must fix the underlying issue.
- **Activity Log**: App-wide via shared `utils/activity_log.rs` module. Two emission helpers: `emit_download_log(app, download_id, message)` for per-download events, `emit_app_log(app, message)` for system-level events (uses `download_id: "system"` sentinel). Frontend renders `[System]` badge in `text-status-info` colour for system entries. Covers: update checks, dependency installs, cookie imports, settings saves, queue operations (enqueue/cancel/retry/clear/export/import), login window, pre-flight checks, app startup, and queue recovery. The `ActivityLogEvent` struct and helpers were refactored from `download_queue.rs` private scope to shared utility for cross-module use. No entry cap (previously 5,000 in `activityStore.ts`). Queue item demarcation: separator line emitted at start of each download. Export filename: `MeedyaDL-activity-log_YYYY-MM-DD_HHhMMm.log` (`.log` extension, timestamped).
- **Error classification**: `process::classify_error()` returns category strings used for retry strategy and UI display. Categories: `auth`, `io`, `network`, `codec`, `not_found`, `rate_limit`, `tool`, `unknown`. Network detection covers: "network", "timeout", "timed out", "connection", "connecterror", "dns", "httpx", "httpcore". The httpx/httpcore keywords catch any error from Python's HTTP transport libraries (including raw traceback frames containing these library paths).
- **Error extraction**: In `download_queue.rs`, `extract_python_exception()` is ALWAYS tried against raw stderr (not just when `errors.last()` contains "traceback"). This handles cases where the output parser captures a traceback frame as the last error instead of the actual exception. The output parser's Priority 7 keyword matching skips lines starting with `File "` (Python traceback frames) to prevent function names like `map_httpcore_exceptions` from triggering the "exception" keyword.
- **Sentry** (opt-in): `sentry_enabled` setting (default: `false`). When enabled, Rust SDK + JS SDK send anonymous crash data. Toggle in Settings > Advanced. Exists as a parallel path alongside the GitHub Issues reporting.
- **Cancellation handling**: When a download is cancelled, the error handler short-circuits on the sentinel string `"Download cancelled by user"` — it only decrements `active_count` without overwriting the already-set `Cancelled` state or creating an error report.
- **URL validation**: URLs are validated as starting with `http://` or `https://` before being passed to GAMDL subprocess in `gamdl_service.rs`. Prevents `--`-prefixed strings from being misinterpreted as CLI flags.
- **Credential redaction**: `redact_url_query()` strips query parameters from wrapper URLs before logging, preventing authentication tokens from persisting in plaintext log files.
- **Timeout safety**: All HTTP clients use explicit timeouts — `download_file()` uses 30s connect timeout, health check uses 5s, GitHub API uses 15s, `pip show gamdl` uses 10s. Prevents indefinite blocking on unresponsive servers or network mounts.
- **Log retention**: Log files are cleaned up after 7 days by `clear_old_logs()` at startup, matching the crash report retention policy. `tracing_appender::rolling::daily()` creates files but never deletes them.
- **CI hardening**: `workflow_dispatch` inputs in `release.yml` and `version-bump.yml` are passed via `env:` variables, not direct `${{ }}` shell interpolation, preventing injection attacks from collaborators. All release-critical GitHub Actions are pinned to immutable commit SHAs (not mutable version tags like `@v4`) across all 5 workflow files — prevents supply chain attacks where a compromised action tag could inject malicious code into CI/CD pipelines. `cargo-deny` licence scanning via `deny.toml` runs in the CI backend job to enforce a permissive licence allowlist. CodeQL workflow requires `actions: read` permission alongside `security-events: write` and `contents: read` for the analyze job to access workflow run telemetry.
- **INI injection prevention**: `sanitize_ini_value()` in `config_service.rs` strips `\n` and `\r` from all user-provided string values before writing to GAMDL's config.ini. Prevents INI key injection via crafted settings import files.
- **HTML sanitization**: `rehype-sanitize` in `HelpViewer.tsx` strips dangerous HTML elements (script, iframe, event handlers) while allowing safe ones (details, summary) via a custom allowlist schema.
- **Import validation**: `sanitize_imported_settings()` in `commands/settings.rs` truncates paths (1024), URLs (2048), templates (512), language (20), storefront (10), and strips control characters from all imported fields.
- **Atomic file writes**: Both `settings.json` and `queue.json` use write-to-temp-then-rename pattern (`std::fs::write` to `.json.tmp`, then `std::fs::rename`) for crash/power-loss safety.
- **Queue debounce**: `save_queue_to_disk()` saves at most once per 500ms via `AtomicU64` timestamp, with a delayed follow-up save to ensure final state is persisted. Reduces I/O pressure from rapid queue mutations.
- **No shell interpolation**: All subprocess calls use parameterised `Command::new().arg()` — no `sh -c format!()` patterns. The two former `sh -c` invocations in `dependency_manager.rs` (GPAC cpio extraction and .deb tar extraction) were replaced with direct process invocations.
- **Modal focus trap**: `Modal.tsx` has `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, Tab/Shift+Tab focus cycling, auto-focus on open, and focus restore on close.
- **SECURITY.md**: Vulnerability reporting policy with responsible disclosure instructions, supported versions, and comprehensive security measures list.
- **Premium feature token resolution**: `TokenSource` enum in `apple_music_api.rs` with 3-tier priority for features that need a developer token (syllable-lyrics, animated artwork, music video relations): (1) User-provided MusicKit credentials (`UserProvided`), (2) Compile-time embedded token (`option_env!("APPLE_DEVELOPER_TOKEN")`) (`Embedded`), (3) Web player-extracted token from OS keychain (`WebPlayer`). `resolve_premium_feature_token()` returns `Option<(String, TokenSource)>`. The web player token is opportunistically extracted during Apple Music login via `login_window_service.rs` — JavaScript evaluation on the WebView captures the `MusicKit.getInstance().developerToken` value, which is then stored in the OS keychain (`webplayer_developer_token` key) via `keyring` crate. Token is NOT used for basic catalog API calls (those always use user-provided MusicKit JWT); only for premium features as a last-resort fallback. IPC commands: `has_webplayer_token` (checks keychain), `clear_webplayer_token` (removes from keychain) in `commands/credentials.rs`.
- **Dev access mode**: Hidden developer tools activation via Konami code sequence (arrow keys + BA) in the frontend. `useKonamiCode.ts` hook listens for the key sequence and triggers a passphrase modal. Passphrase validated via SHA-256 hash comparison (hash stored in code, never the plaintext). On successful activation: sets `dev_access_enabled: bool` in AppSettings + writes a keychain sentinel (`dev_access_sentinel` key). `check_dev_access` IPC reads the keychain sentinel (survives settings reset). `activate_dev_access` / `deactivate_dev_access` IPC commands toggle both settings and keychain. Gates a "Developer Tools" section in `AdvancedTab.tsx` (`DevToolsSection` component) showing: web player token status (present/absent + clear button), token source hierarchy visualization, and diagnostic info. Section only renders when `dev_access_enabled` is true.
- **Regex caching**: `parse_apple_music_url()` in `apple_music_api.rs` uses `static LazyLock<Regex>` for one-time compilation instead of per-call `Regex::new().expect()`.
- **SHA-256 checksum verification**: `download_file()` in `archive.rs` computes SHA-256 during streaming download (zero extra I/O pass) using the `sha2` crate. Returns `(bytes_downloaded, sha256_hex)`. `download_and_extract_verified()` accepts an optional expected hash and verifies after download, before extraction — mismatch deletes the temp file and returns an error. Infrastructure-only for now; callers can opt in by passing `expected_sha256`.
- **Graceful shutdown**: `ShutdownSignal` in `download_queue.rs` wraps `Arc<AtomicBool>` with `trigger()` / `is_triggered()` methods. Registered as Tauri managed state. Triggered on `WindowEvent::Destroyed` and tray "quit" action. Checked at iteration boundaries in enrichment pipeline (between 8 stages), companion download loops (between tiers), and lyrics companion loops (between formats). Fire-and-forget `tokio::spawn` tasks exit early instead of starting new work after shutdown.
- **Download manifest files (.meedyadl)**: After enrichment, a `.meedyadl` JSON manifest is written to each album output directory via `write_manifest()` in `download_queue.rs`. Records source URL, platform, storefront, per-track metadata (ISRC, title, individual URLs). Multi-platform merge-safe — new platform sources append to existing manifests. MIME type: `application/vnd.mwbmpartners.meedyadl.download+json`. Import via "Import" button on Download page (`import_manifest` IPC command), drag-and-drop `.meedyadl` files, or OS file association (deep link handler). File association registered in `tauri.conf.json`. Schema version 1 with `sources[]` array (distinct from queue export which uses `items[]`). `downloaded_at` captures download start time, `codec` defaults to null (manifest is a metafile, not a quality prescription). Document type icons: `icon-doc.svg/png/icns/ico` in `assets/brand/`.
- **Output detection fallback**: `find_album_directory()` disk-scan fallback runs before terminal failure check when GAMDL exits 0 without "Saved to:" lines (GAMDL 2.9.x with native `--song-codec-priority` for albums). Prevents false "no output files" errors and cascading auto-retry that could overwrite higher-quality files.
- **Wrapper auth logging**: At download start, a non-verbose `emit_download_log()` entry shows the active authentication method: "Authentication: Wrapper ({redacted_url})" or "Authentication: Cookie-based (no wrapper)".
- **Smart re-download detection**: When `smart_redownload_detection` is enabled (default: `true`), `DownloadForm.tsx` checks the download history before queueing a URL. If the URL was previously downloaded, shows an info toast with the original download date. The Apple Music API's `lastModifiedDate` field is extracted during enrichment and stored in the `.meedyadl` manifest (`ManifestSource.last_modified_date`) and as `AlbumLastModified`/`AppleLastModifiedDate` atoms in M4A files. Detects: audio quality upgrades, tracks added, metadata corrections, Apple Digital Master certification. Cannot detect: silent audio remasters without metadata changes. Toggle in Settings > General > Preferences. IPC: `check_redownload_status(url)` in `commands/gamdl.rs`.

## Conventions

- **Copyright header**: Every source file starts with `// Copyright (c) 2026 MeedyaDL` + MIT license reference
- **Comments**: Every function and significant code block gets detailed comments
- **Conventional commits**: Required for automated changelog generation (release-please)
- **GAMDL options**: All 11 audio codecs, 8 video resolutions, all CLI flags typed as Rust enums in `models/gamdl_options.rs`. Includes `song_codec_priority` (for GAMDL >= 2.9.1 native multi-codec support) and `artist_auto_select` (7 variants: main-albums, compilation-albums, live-albums, singles-eps, all-albums, top-songs, music-videos). **Multi-select artist auto-select**: `artist_auto_select_multi: Vec<ArtistAutoSelect>` stores multiple modes; when downloading from an artist URL with multiple modes selected, `start_download` creates N separate queue items (one per mode) since GAMDL only accepts a single `--artist-auto-select` value. Legacy `artist_auto_select` field kept in sync for backwards compatibility.
- **Fallback quality chains**: Version-aware strategy with safety net. For GAMDL >= 2.9.1: first attempt uses native `--song-codec-priority` flag to pass the entire fallback chain (e.g., `atmos,alac,aac,...`) in a single process invocation. If native priority fails, MeedyaDL's own `try_fallback` system kicks in as a safety net, retrying each codec individually via `--song-codec-priority <single-codec>`. For GAMDL < 2.9.1: MeedyaDL's `try_fallback` is the only mechanism. `try_fallback()` returns `Option<(GamdlOptions, usize, usize)>` — the new options, 1-indexed fallback position, and chain length. Activity log shows: "Format not available — trying {codec} (fallback {n} of {total})". Music chain: ALAC→Atmos→AC3→AacBinaural→Aac→AacLegacy; Video: 2160p→...→240p. Config.ini dual-key strategy writes both `song_codec` (for < 2.9.1) and `song_codec_priority` (for >= 2.9.1) to ensure compatibility across GAMDL versions. **Gap-fill retry**: When native priority partially succeeds (some tracks downloaded, some skipped due to experimental codecs without wrapper), MeedyaDL automatically re-runs GAMDL with `overwrite=false` and a filtered priority chain excluding wrapper-dependent codecs (Atmos, AC3). This fills gaps with lossless/lossy fallbacks without overwriting successful experimental-codec downloads. Helpers: `count_codec_skip_warnings()`, `build_gapfill_priority_chain()`, `count_audio_files_in_directory()`. `SongCodec::is_wrapper_dependent()` identifies codecs requiring wrapper auth. `SongCodec::from_cli_string()` parses CLI strings back to enum variants.
- **Apple Music URL support**: Three domains accepted: `music.apple.com` (standard), `classical.apple.com` (Apple Music Classical), and `itunes.apple.com` (legacy). Validated in both the frontend URL parser (`src/lib/url-parser.ts`) and backend regex patterns in the Rust services. **Non-geographic URLs** (missing storefront code, e.g., `music.apple.com/album/...`) are auto-normalized at enqueue time by injecting a storefront based on OS locale (or `"us"` fallback) via `normalize_apple_music_url()` in `apple_music_api.rs`. GAMDL requires the storefront for its URL regex but ignores it for API calls (uses cookies/wrapper auth). Enrichment API calls use `fetch_album_metadata_with_fallback()` which retries with alternative storefronts (OS locale, `"us"`) when the primary returns 404 — handles region mismatches from shared links. **Personal library URLs** (`/library/albums/l.XXXX`, `/library/songs/...`) are accepted as `'library'` content type by the frontend URL parser and passed through to GAMDL as-is.
- **Companion downloads**: Configurable via `CompanionMode` enum (Disabled / AtmosToLossless / AtmosToLosslessAndLossy / SpecialistToLossy / AtmosToAllFormats / Custom) in `settings.rs`. Default: `AtmosToLossless` (Atmos → also download ALAC). The `plan_companions()` function in `download_queue.rs` returns a list of `CompanionTier` structs; each tier's codecs are tried in order. When companions exist, primary gets suffix (`[Dolby Atmos]` or `[Lossless]`); most universal companion uses clean filenames. `spawn_companion_downloads()` returns a `JoinHandle` tracked by the completion task; queue item stays in `Processing` state until all companions AND enrichment finish. Companion stdout is streamed line-by-line and emits `gamdl-output` progress events (speed/ETA/percentage visible in GlobalProgressBar). Suffix system via `codec_suffix()` (delegates to `codec_suffix_from_registry()` in `codec_registry.rs`), `apply_codec_suffix()`, and `needs_primary_suffix()` in `download_queue.rs`. Codec suffixes are defined in `codecs.toml` (e.g., ALAC → `[Lossless]`, Atmos → `[Dolby Atmos]`, AC3 → `[Dolby Digital]`, AAC Binaural → `[Binaural]`, AAC Downmix → `[Downmix]`, AAC Legacy → `[AAC Legacy]`, HE-AAC → `[HE-AAC]`); empty string means clean filenames (no suffix). **Custom mode**: Users select specific codecs via `custom_companion_codecs: Vec<SongCodec>` setting; each selected codec becomes its own `CompanionTier` (all user selections respected, including the primary codec — with native priority the actual codec may differ); the last codec in the list gets a clean filename, others get suffixes. Companion downloads are **skipped when the primary download fails with a network error** — since the network is unavailable, companions would also fail (wasting ~3 min per item on GAMDL timeouts). Activity log: "Companion downloads skipped — network unavailable". Per-tier codec details are logged before spawning ("Companion tier 0: trying ac3, alac, aac"), per-codec attempts during execution ("Companion tier 0: attempting ac3..."), and per-codec failures on non-zero exit ("Companion tier 0: ac3 failed — {error}"). Desktop notifications deferred until the completion task finishes (all companions + enrichment).
- **Metadata enrichment**: After GAMDL writes standard tags, a unified background task runs 12 enrichment stages via `metadata_tag_service.rs`, `enhanced_lyrics_service.rs`, `webvtt_service.rs`, `rich_srt_service.rs`, `ass_subtitle_service.rs`, `acoustid_service.rs`, `replaygain_service.rs`, `apple_music_api.rs`, `mediainfo_service.rs`, and `musicbrainz_service.rs`: (1) codec/source/channel tags + Apple Music API metadata (always-on; uses ffprobe-based codec detection via `detect_audio_info()` + `resolve_codec_from_ffprobe()` when native priority is active to determine the ACTUAL codec GAMDL selected, rather than trusting the requested codec), (1a) API response JSON dump (verbose-only diagnostic — writes `<AlbumName>-applemusic-data.json` to the album output directory when `verbose_activity_log` is enabled, containing the raw Apple Music API response for debugging endpoint changes), (1b) syllable-lyrics API fetch (automatic when Enhanced LRC is on — upgrades TTML to word-level timing via `/syllable-lyrics` endpoint if GAMDL's output lacks it), (2) Enhanced LRC conversion (opt-in, `enhanced_lrc`, default on), (2b) lyrics format fallback (opt-in, `lyrics_fallback_enabled`, default on — retries with LRC/SRT if TTML didn't produce lyrics for all tracks), (2c) WebVTT subtitle generation (opt-in, `generate_webvtt` — converts TTML/SRT/LRC to `.vtt`), (2d) Rich SRT generation (opt-in, `generate_rich_srt`, default on — TTML → SRT with bold/italic/underline/colour styling tags, overwrites plain SRT), (2e) subtitle embedding (opt-in, `embed_subtitles` — embeds SRT/VTT sidecar content as freeform atoms in MP4 containers), (2f) ASS subtitle generation (opt-in, `generate_ass` — converts TTML/SRT/LRC to `.ass` with styled formatting), (3) animated artwork download (reuses API response), (4) AcoustID fingerprinting (opt-in, `acoustid_enabled`), (5) ReplayGain analysis (opt-in, `replaygain_enabled`), (6) music video companion downloads (opt-in, `music_video_companion`, requires MusicKit credentials), (6b) MusicBrainz video discovery fallback (opt-in, `musicbrainz_lookup` — 3-tier: Apple Music URL → ISRC → AcoustID recording ID). All use `mp4ameta` crate freeform atoms via `set_data()` + `write_to_path()` which preserves existing tags. Shared API logic in `apple_music_api.rs` (MusicKit JWT, URL parsing, catalog fetch, music video relation lookup). The `AlbumMetadata` struct (20+ fields including record label, copyright, editorial notes, release dates, compilation/single/complete flags, MFiT status, track count) and `TrackMetadata` struct (20+ fields including ISRC, audioTraits, Apple Digital Master flag, composer, duration, genres, play params, URLs) are fetched once and shared across enrichment, artwork, and music video companion lookup to avoid duplicate API calls. All Apple-specific metadata is embedded under the `MeedyaMeta` freeform atom namespace with `Apple` prefix (e.g., `MeedyaMeta:AppleRecordLabel`, `MeedyaMeta:AppleDigitalMaster`). **AcoustID API key**: Resolved via `resolve_api_key()` in `acoustid_service.rs` — user override (Settings > Metadata) takes priority, then compile-time embedded key (`option_env!("ACOUSTID_API_KEY")`), then `None` (skipped). Release builds embed the key from a GitHub Actions secret. The `has_embedded_acoustid_key` Tauri command lets the frontend detect whether a built-in key exists.
- **WebVTT subtitles**: When `generate_webvtt` is enabled (default: `false`), enrichment Step 2c generates WebVTT (`.vtt`) subtitle files from existing lyrics sidecars. Source priority: TTML (richest timing, with `<span>` word-level support), SRT (has start+end times), LRC (start times only, 3s estimated durations). Service in `webvtt_service.rs`, toggle in Settings > Lyrics.
- **MusicBrainz lookup**: When `musicbrainz_lookup` is enabled (default: `false`), enrichment Step 6b discovers music videos and cross-platform URLs via the MusicBrainz database. Uses a 3-tier priority chain: (1) Apple Music URL search in MB external links (highest fidelity), (2) ISRC code search (standard identifier), (3) AcoustID recording ID direct lookup (from Step 4 fingerprinting). No credentials required (free public API). Rate-limited to 1 request/second. Returns `MusicBrainzRecording` with `external_urls: HashMap<String, String>` for cross-platform discovery (Apple Music, YouTube, Spotify, Deezer, Tidal, SoundCloud, Bandcamp). Storefront-aware: rewrites Apple Music URLs to match the user's configured storefront. Service in `musicbrainz_service.rs`, toggle in Settings > Quality > Video Quality.
- **Music video companions**: When `music_video_companion` is enabled (default: `false`) and MusicKit credentials are configured, enrichment Step 6 queries the Apple Music API for music video relationships (`fetch_music_video_relations()` in `apple_music_api.rs`). Songs with music videos get a companion GAMDL download spawned with the music video URL, using the user's video quality settings. Deduplicated by video ID. Fire-and-forget (failures logged, don't affect primary download). Toggle in Settings > Quality > Video Quality, greyed out when MusicKit credentials not configured.
- **Enhanced LRC**: When `enhanced_lrc` is enabled (default: true), `merge_options()` Layer 4 forces TTML as the primary lyrics format so GAMDL preserves Apple Music's word-level timing data. After download, `enhanced_lyrics_service.rs` parses the TTML via `roxmltree`, extracts `<span>` word timestamps from `itunes:timing="Word"` documents, and generates Enhanced LRC with inline `<mm:ss.xx>` word timing. The `.lrc` sidecar is saved and embedded in M4A/M4V via the `©lyr` atom. Songs without word-level timing gracefully fall back to standard line-level LRC. **Syllable-lyrics API fallback** (enrichment Step 1b): When GAMDL's TTML output lacks word-level timing (`itunes:timing="Word"`), the enrichment pipeline fetches syllable-level TTML directly from Apple Music's `/syllable-lyrics` API endpoint (`fetch_syllable_lyrics()` in `apple_music_api.rs`). Requires both MusicKit developer credentials (JWT) and a `Music-User-Token` extracted from imported browser cookies (`extract_media_user_token()` parses the Netscape cookies file with expiry validation). Upgraded TTML sidecars are written before Enhanced LRC conversion runs. Rate-limited at 200ms between requests. Silently skipped when credentials or cookies are unavailable.
- **Lyrics embed + sidecar**: When enabled in settings, `merge_options()` forces `no_synced_lyrics=false` and removes `"lyrics"` from `exclude_tags` to ensure both embedded lyrics and sidecar files are created.
- **Content advisory suffixes**: When `content_advisory_in_filenames` is enabled (default: `true`), `apply_advisory_suffixes()` in `metadata_tag_service.rs` renames album folders and track files with `[Explicit]` or `[Clean]` suffixes after metadata is fetched during enrichment. Per-track granularity via `TrackMetadata.content_rating`; album folder via `AlbumMetadata.content_rating`. Advisory suffix inserted BEFORE codec suffix: `01 Title [Explicit] [Lossless].m4a`. Idempotent (won't double-suffix). Queue item's `output_path` updated after folder rename so "Open Folder" still works. Toggle in Settings > Metadata.
- **Queue progress indicators**: Queue header statistics bar displays active/queued/completed/failed counts with an aggregate progress bar showing the completed/total ratio. `QueueItem` shows a "Track N of M" counter for album downloads, extracted from GAMDL progress output.
- **Queue auto-start**: Controlled by `auto_start_queue` setting (default: `true`). When enabled, `process_queue()` is called immediately after enqueue in `start_download()`, `retry_download()`, and `import_queue()`. When disabled, items stay in `Queued` state until the user clicks "Start Queue" in the Queue page (calls `process_queue_manual` command). Startup queue recovery always runs regardless of this setting.
- **Temp directory**: `temp_path` setting (default: empty string, resolved to `{OS temp dir}/MeedyaDL`). Resolved at runtime in both `merge_options()` and `settings_to_ini()` via `std::env::temp_dir().join("MeedyaDL")`. Avoids GAMDL's default of `.` which is unwritable on macOS from `/Applications`. Configurable in Settings > Tools.
- **Queue persistence**: The download queue is saved to `{app_data_dir}/queue.json` after every mutation (enqueue, cancel, retry, clear, completion, error, fallback). On startup, `load_queue_from_disk()` restores items and `process_queue()` is called after a 2-second delay (to let frontend event listeners initialise). Active items (Queued/Downloading/Processing) and failed items (Error) are persisted; only Completed and Cancelled items are cleared on restart. Failed items are restored in their Error state with the original error message so the user can review the failure and manually retry — they are not auto-retried. `PersistedQueueItem` includes an optional `error` field (`#[serde(default)]` for backwards compatibility with older `queue.json` files). Uses clone-then-release pattern: clone persistable items from lock, release lock, then write to disk. **Important**: Queue restoration in `setup_queue_recovery()` uses `blocking_lock()` (not `block_on(lock().await)`) and `tauri::async_runtime::spawn` (not `tokio::spawn`) because the Tokio runtime may not be registered as "current" during the `setup` closure on macOS.
- **Queue export/import**: Export via `export_queue` command opens native save dialog with `.meedyadl` filter; writes `QueueExportFile` JSON (version, app, exported_at, items). Import via `import_queue` opens native file picker, validates schema version == 1, re-enqueues items with fresh settings merge. Exported items contain only URLs + per-download overrides (not merged options), so the importing device uses its own settings as base. **Clear All**: `clear_all_queue` IPC command with confirmation modal removes all non-active items (queued, completed, cancelled, errored); active downloads preserved. Separate from "Clear Completed" which only clears complete+cancelled.
- **Hidden animated artwork**: After downloading FrontCover.mp4/PortraitCover.mp4, files are hidden via OS-native mechanisms if `hide_animated_artwork` is `true` (default). macOS: `chflags hidden` (preserves filename); Windows: `attrib +H` (preserves filename); Linux: `.` prefix rename (changes filename). Logic in `animated_artwork_service::hide_file()`, called from the artwork background task in `download_queue.rs`.
- **Dependency manager**: 4 required external tools (FFmpeg, mp4decrypt, N_m3u8DL-RE, MP4Box). `tool-versions.toml` defines minimum supported versions per tool and mirror config (compiled into binary via `include_str!()`). Download resolution follows a three-tier fallback chain: **System PATH** → **Primary upstream** → **Mirror repo** (`MeedyaDL/MeedyaDL-Tools`) → Error with guidance. `resolve_github_release_asset()` is the generic GitHub API resolver used by both upstream (N_m3u8DL-RE) and mirror queries. `install_tool()` first checks system PATH for a compatible version; if found, copies it to the managed tools dir and writes a `.source` marker file ("system"); otherwise downloads (with mirror fallback) and writes "managed". `DependencyStatus.source` field (Rust + TypeScript) drives the "System" badge in the setup wizard. MP4Box uses platform-specific installers (macOS Homebrew/`.pkg`, Windows NSIS `.exe`, Linux x86_64 `.deb`, Linux ARM `apt-get install gpac`) with mirror fallback via `install_mp4box_with_fallback()`. Mirror assets use standardized naming: `{tool_id}-{os}-{arch}.{ext}`. AcoustID fingerprinting uses the embedded `rusty-chromaprint` library (pure Rust) — no external fpcalc binary needed.
- **Periodic update checks**: `update_check_interval_hours` setting (default: `6`, configurable in Settings > General when "Auto-Check for Updates" is enabled). Options: Startup only (0), Every hour (1), Every 6 hours (6), Every 12 hours (12), Every 24 hours (24). Implemented as a `setInterval` timer in App.tsx Effect 4 alongside the existing startup check. The interval reads settings imperatively via `getState()` and guards against concurrent checks with `isChecking`. Changes take effect on app restart. Value `0` disables the periodic timer (startup check only). Rust field: `update_check_interval_hours: u32` with `#[serde(default = "default_update_interval")]` for backwards compatibility.
- **Updates page**: Dedicated sidebar page (`src/components/updates/UpdatesPage.tsx`) showing full release notes rendered via `react-markdown`. Strips the "Choose your download" section from release bodies since the in-app updater handles downloads. Connected to the update banner's "View Details" link and the sidebar footer's update button. External links in rendered release notes use a custom `ReactMarkdown` `components.a` handler that intercepts HTTP(S) clicks and opens them in the system default browser via `@tauri-apps/plugin-shell` (same pattern as `HelpViewer.tsx`). The "View on GitHub" buttons in both `UpdatesPage.tsx` and `UpdateBanner.tsx` also use the shell plugin instead of `window.open()`.
- **Drag-and-drop URL input**: Content area in `MainLayout.tsx` accepts Apple Music URLs dragged from browsers. Uses `dragenter`/`dragleave` counter pattern to prevent overlay flicker. Validates via `parseAppleMusicUrl()`, navigates to Download page and populates input on valid drop.
- **Batch URL paste**: `DownloadForm.tsx` uses `<textarea>` for multi-URL input. Each line validated as Apple Music URL, queued as separate download. Enter submits, Shift+Enter inserts newline.
- **Download history**: `history_service.rs` persists download history as JSON (max 1000 entries). `HistoryPage.tsx` displays with search, status icons, codec badges. Sidebar nav between Queue and Activity.
- **Duplicate URL detection**: `normalize_url_for_dedup()` and `has_duplicate_urls()` in `download_queue.rs`. Warning toast on duplicate, download still allowed.
- **Native desktop notifications**: `tauri-plugin-notification`. Triggers on download complete/error and queue complete. `desktop_notifications` setting (default: `true`).
- **Deep links**: `meedyadl://` custom URL scheme via `tauri-plugin-deep-link`. Parses Apple Music URLs and navigates to Download page.
- **Keyboard shortcuts**: `useKeyboardShortcuts.ts` hook. Cmd/Ctrl+D (download), Cmd+, (settings), Cmd+Q (queue).
- **Settings sidebar categories**: Settings page sidebar grouped into sections (General, Download, Authentication, System) with headers.
- **Accessibility**: High-contrast mode (`high_contrast` setting, `a11y-high-contrast.css`), colour blindness themes (`colour_blind_mode`: normal/deuteranopia/protanopia/tritanopia, `a11y-colour-blind.css`), `prefers-reduced-motion` media query, WCAG 2.4.1 skip navigation link. `.hintrc` suppresses Edge DevTools false positives.
- **Storefront configuration**: `storefront` setting in AppSettings. Auto-derived from `language` region code (e.g., en-GB → gb), fallback "us". Written to GAMDL config.ini `[metadata]` section — required by GAMDL 2.9.3+. Configurable in Settings > General.
- **Global progress bars**: `GlobalProgressBar.tsx` renders dual progress bars between `<main>` and `<StatusBar>` in `MainLayout.tsx`. Upper = per-item progress (accent blue), lower = queue-level (green). Auto-hides when no downloads active. Shows percentage for both bars. Apple Music platform icon (inline SVG via `detectPlatform()` with config from `engines.toml` via IPC) displayed next to track name, extensible for future services. **Companion speed/ETA**: During companion downloads, the per-item bar shows speed, ETA, and percentage (not indeterminate) — the store preserves `processing` state stability so queue-level progress doesn't oscillate. Speed/ETA are cleared on `processing_step` transitions to avoid stale data during enrichment. `processing_label` field on `QueueItemStatus` drives the label display (e.g., "Enriching metadata...", "Companion: ALAC 14/28"). - **ISRC handling**: `extract_isrc_from_vendor()` in `metadata_tag_service.rs` with 3-case logic: (1) ISRC blank → copy from Vendor, (2) ISRC set + differs → store both, (3) match or no Vendor → no-op.

Template-based approach broke GAMDL; files are renamed after download instead. `enrich_single_file()` returns the ffprobe-detected `SongCodec`; the post-enrichment suffix rename uses the per-file detected codec (not the requested codec). This prevents incorrect suffixes when native priority falls back silently (e.g., `[Dolby Atmos]` on ALAC files).

## Release Workflow

```text
Push fix:/feat: commits directly to main
  → release-please creates/updates a Release PR (bumps versions)
  → User reviews and merges the Release PR
  → release-please creates tag (e.g., v0.3.0) using RELEASE_PAT
  → release.yml triggers → 6 platform builds → draft GitHub Release
  → changelog.yml triggers → git-cliff regenerates CHANGELOG.md
```

Manual override: `version-bump.yml` + `scripts/bump-version.mjs` for non-standard releases.

### Conserving GitHub Actions Minutes

All workflows (CI, Changelog, Release Please, Release) support both automatic (`on: push`) and manual (`workflow_dispatch`) triggers.

**Do NOT use `[skip ci]`** in commit messages unless the user explicitly requests it. Every push must trigger CI to validate changes. Manual triggering is available if needed:

```bash
gh workflow run "CI" --ref main
gh workflow run "Release Please" --ref main
gh workflow run "Changelog" --ref main
gh workflow run "Release" -f tag=v0.3.3  # Release requires a tag input
```

### Release Please Branch Naming

Release-please v4 creates PR branches with the format:
`release-please--branches--{target}--components--{component}`

For this project (component name from `package.json` `name` field):
`release-please--branches--main--components--meedyadl`

The `.release-please-manifest.json` must match the current version to avoid release-please trying to create releases from an old version.

## Important Notes

- Rust env: `export PATH="$HOME/.cargo/bin:$PATH"` (not `source "$HOME/.cargo/env"` — fails in zsh sandbox)
- Icons generated from `assets/icons/app-icon.svg` via `scripts/generate-icons.mjs` (requires `sharp` — install temporarily with `npm i sharp`)
- All settings stored as JSON in platform app data directory
- GAMDL config.ini is synced from GUI settings
- CSP in `tauri.conf.json` must include `connect-src ipc: http://ipc.localhost` for IPC
- Vite build config uses `TAURI_ENV_PLATFORM` for platform-specific JS targets (safari16.4 / chrome111)
- `devtools` Cargo feature enabled for WebView inspection in release builds
- **macOS codesign `--timestamp` workaround**: Tauri's `tauri-macos-sign` crate omits `--timestamp` from `codesign` calls, causing non-deterministic notarization failures ([tauri#11992](https://github.com/tauri-apps/tauri/issues/11992)). Both `release.yml` and `pre-release.yml` include a PATH-based wrapper script (Step 8.9) that intercepts `/usr/bin/codesign` and injects `--timestamp` automatically. Remove the wrapper once the upstream Tauri fix lands.
